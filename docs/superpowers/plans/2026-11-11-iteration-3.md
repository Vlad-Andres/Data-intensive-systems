# Iteration 3 — courses hosted by the portal, custom components, code runners

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking. Packages in order Z → F → G → H → I.

**Goal:** A finished job is a live course at `https://<portal>/courses/<course-key>/`, rendered by the portal from stored JSON with the template's own components; the model may add sandboxed custom components and code-runner exercises.

**Architecture:** The template's UI stops importing build-time JSON and takes a `SiteData` value through props and a React context, so the same components render both the template's static export and the portal's `/courses/[key]` routes. The portal vendors that UI (like `vendor/core`) and publishes a course by writing `courses/<key>/site.json` to Blob through a new `portalPublisher` that implements the existing `Publisher` interface. Custom components are HTML documents run in `<iframe sandbox="allow-scripts" srcdoc>` with an injected CSP that forbids network access.

**Tech stack:** Next.js 16 (both repos; read `node_modules/next/dist/docs` before using an API), React 19, Zod 4, Tailwind 4 (template UI), Vercel Blob, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-10-learning-playground-platform-design.md`, section **"Amendments 2026-11-11 (b)"** (wins over everything above it). Progress so far: `docs/superpowers/ledger-iteration-2.md`; state: `docs/superpowers/NEXT.md`.

## Global Constraints

- No secret, key, token or access code in any file, commit, log, error message or client bundle. Never print a `.env*` file. **Never write an absolute local path (`/Users/...`) into either repo.**
- Model output and course material are untrusted: never `eval`/`new Function` them in the page, never render raw HTML outside the sandboxed iframe, never put a model URL in `src`/`href` without the `http(s)` check.
- Model-written code runs **only** inside `<iframe sandbox="allow-scripts">` (never `allow-same-origin`, never `allow-top-navigation`, never `allow-popups`, never `allow-forms`), with the CSP from Task G2.

## Review Focus

1. **A custom component that tries to escape** (`fetch`, `new WebSocket`, `top.location = …`, `document.cookie`, `localStorage`, a `<form>` posting away, an `<img src="https://…">` beacon) must do nothing outside its frame and must not break the page. Tested in G1 (static scan), G2 (CSP string) and by hand in H4.
2. **Two generated courses with the same `course.id`** (two users upload the same textbook) must not share progress, flags or quiz state in one browser. Storage is namespaced by the **course key**, not `course.id`. Tested in F2 and H2.
3. **Unknown or malformed course keys** (`../x`, `ABC-1234abcd`, a deleted course) give a 404 page, never a crash or a Blob error. Tested in H3.
4. **Republish and takedown with cached pages**: after takedown the course is gone within one request, not after the cache expires. Tested in H5.
5. **Messages from the wrong frame**: `CustomFrame` only accepts `postMessage` events whose `source` is its own iframe. Tested in G2.
6. **Template styles leaking into the portal's own pages** (Tailwind preflight on `/` and `/jobs/*`). Checked by hand in H4.

### Task G2: Sandbox host

**Files:** create `core/sandbox.ts`, `src/components/content/CustomFrame.tsx`, `tests/sandbox.test.ts(x)`; modify `src/components/content/BlockRenderer.tsx`, `src/lib/security.ts` (template CSP: add `frame-src 'self' blob: data:` only if the browser check shows `srcdoc` needs it — record).

**Interfaces (produces):**

```ts
// core/sandbox.ts (pure)
export const SANDBOX_CSP = "default-src 'none'; script-src 'unsafe-inline' {scriptOrigins}; style-src 'unsafe-inline'; img-src data: blob:; font-src data:; connect-src 'none'; form-action 'none'; base-uri 'none'"
export function wrapCustomHtml(html: string, options?: { scriptOrigins?: string[] }): string
// Returns a full document: <meta http-equiv="Content-Security-Policy" content=SANDBOX_CSP> first in <head>,
// then a bootstrap script defining window.pg = { done(score?: number) } and posting to parent:
//   { pg: "ready" } on load, { pg: "height", value } via ResizeObserver, { pg: "error", message } from window.onerror / unhandledrejection, { pg: "done", score }.
export type SandboxMessage = { pg: "ready" } | { pg: "height"; value: number } | { pg: "error"; message: string } | { pg: "done"; score?: number }
export function parseSandboxMessage(data: unknown): SandboxMessage | null   // strict: anything else → null
// src/components/content/CustomFrame.tsx ("use client")
export function CustomFrame(props: { title: string; description: string; html: string; height?: number; scriptOrigins?: string[] }): JSX.Element
// <iframe sandbox="allow-scripts" srcDoc={wrapCustomHtml(html)} title={title} referrerPolicy="no-referrer">;
// accepts a message only when event.source === iframe.contentWindow; height clamped to 200..900;
// on "error" shows "This exercise hit an error" with the message as text; on "done" shows a check mark.
```
