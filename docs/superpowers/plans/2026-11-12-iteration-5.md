## Technical guidelines (how to build everything in this plan)

Read this section again whenever a task feels open. Every task follows these patterns.

### G1. Code decides, the model proposes

A small model is unreliable. It is never trusted to decide anything a rule can decide. In this plan
**code** decides: the course language; whether to ask a question; which alternatives survive; where a
custom exercise is allowed; whether a reorganisation is proposed; every limit and count. The model
only fills validated JSON. If you find yourself asking the model "is X ambiguous?" or "are these
different enough?", stop: write a rule instead.

### G2. The shape of every model call

Every model call in `core/generate/` is built the same way. Copy `planCourse` in
`core/generate/plan.ts`; do not invent another shape.

1. A prompt function in `prompts.ts` returns `{ system, user }`. `system` starts with a `TASK`
   constant (so the fake model can tell calls apart), then one sentence of role, then the existing
   `SAFETY` text, then the exact JSON shape, then short rules. `user` holds the data.
2. One call through `ModelClient.complete`, parsed with `extractJson`.
3. A `prepare` step where **code overwrites** every field the model must not control.
4. Validation with a Zod schema.
5. On failure: **one** more call with the problems listed. Never a third.
6. On a second failure: the fallback the task names (a default value, a dropped item, or an `Error`
   with the exact message the task gives). Never invent content in a fallback.

A call sees only what it needs: validated results of earlier calls and the pages it is about. Never
pass a whole earlier reply, never pass "the conversation".

**Call budget per job** (the existing token budget `DEFAULT_BUDGET` stays as it is):

| Job | Model calls at most |
| --- | --- |
| Create | 2 (context) + 2 (design) + 2 (expand, only when an alternative is chosen) + 4 per lecture |
| Refine | 2 (plan) + 2 per rewritten lecture, at most 3 lectures |
| Add material | 2 (plan) + 4 per new lecture |

### G3. Storage

There is one store interface, `Store` in `PORTAL/lib/jobs/store.ts` (`read`, `write`, `create`,
`delete`, `list`). Tests use `memoryStore()`. There is no database and no lock service.

- **Anything that must happen at most once** (a refinement round, "this course is being changed") is
  claimed with `store.create(key, body)`, which returns `false` when the key exists. Never read a
  counter, add one and write it back: two requests would both win.
- **Counting** is `store.list(prefix).length`.
- **Write order** for a course change is fixed in `updateCourse` (Task D1). Routes and actions never
  write `site.json` or `meta.json` themselves after D1; they call the library.
- Everything about one course lives under `courses/<key>/`, so `deleteSite` (which deletes that
  prefix) removes all of it.

| Key | Content | Task |
| --- | --- | --- |
| `courses/<key>/site.json`, `meta.json` | the course and its metadata (existing) | — |
| `courses/<key>/brief.json` | the resolved `Brief` the course was built with | D2 |
| `courses/<key>/versions/<n>.json` | an earlier version | D1 |
| `courses/<key>/sources/<n>.json` | one kept file (`Material`) | D2 |
| `courses/<key>/rounds/<1..3>.json` | one claimed refinement round | D3 |
| `courses/<key>/busy.json` | a job is changing this course | D3 |
| `users/<uid>/courses/<key>.json` | "this user owns this course" | C2 |
| `users/<uid>/days/<YYYY-MM-DD>/<jobId>` | one job started by this user that day | C3 |

## Things most likely to go wrong (review these in Task E2)

1. **A weak model reply stops a job.** Every stage must end in a valid result, a dropped item or a
   clear failure code — after at most two calls.
2. **The wrong language.** English slides opened from the Romanian portal must give an English
   course unless the user chose otherwise; mixed material must ask.
3. **Too many questions.** A job with a clear language and a note from the user asks nothing.
4. **Someone else's course.** Every `/my` action and `/api/courses` route with another user's session
   answers 404 and changes nothing.
5. **A round counted twice or lost.** Two refine requests at once use two rounds, never one; a failed
   refinement gives its round back.
6. **A half-written course.** A storage failure in the middle of a change leaves the old course
   readable and valid.
7. **Kept files without consent**, or files that survive switching it off, deleting the course or
   deleting the account.
8. **Old data.** Jobs and courses written before this iteration (step `plan`, no `kind`, a
   `meta.json` without `ownerId`/`version`) keep working.
9. **The preview frame.** It may only ever frame the portal's own course pages, and the course pages
   must stay unframeable by any other site.
10. **Sign-in off.** With the three sign-in variables unset, the portal behaves exactly as after
    iteration 4: no sign-in button, no guest limit, no `/my`.

### Task A2: Detect the language of the material (no model)

**Files:** create `core/generate/language.ts`, `tests/generate-language.test.ts`,
`tests/fixtures/eval/` (five files, below); modify `core/generate/index.ts` (export it).

```ts
// core/generate/language.ts
export const SUPPORTED_LANGUAGES = ["en", "nl", "de", "fr", "es", "it", "pt", "ro", "pl"] as const;
export interface LanguageGuess { kind: "clear" | "mixed" | "unknown"; top: string | null; second: string | null; share: number }
export function detectLanguage(materials: Material[]): LanguageGuess;
export type LanguageDecision =
  | { language: string; source: "user" | "material" | "portal" }
  | { ask: string[] };            // 2 or 3 language codes, no duplicates
export function decideLanguage(input: { requested: string; locale: string; guess: LanguageGuess }): LanguageDecision;
```

`detectLanguage`, exactly:

1. For each page: lower-case the text, remove diacritics (`normalize("NFKD")` and drop
   `\p{M}` characters), split into words on anything that is not a letter (`/[^\p{L}]+/u`).
2. Count, per language, how many words are in that language's list (below; the lists are already
   without diacritics and contain no one-letter words).
3. A page **counts for** its best language when that language has at least 5 hits and at least 1.3
   times the hits of the second-best language. Otherwise the page counts for none.
4. `share` of a language = pages counting for it ÷ pages counting for any language.
5. No page counts → `{ kind: "unknown", top: null, second: null, share: 0 }`. Best share ≥ 0.8 →
   `clear`. Otherwise, second-best share ≥ 0.2 → `mixed`. Otherwise → `clear`.
   `top`/`second` are the best and second-best languages (`second` is `null` when only one scored).

| Code | Words |
| --- | --- |
| `en` | the and of to in is that for with as are this be by on or from which an it can not we has have |
| `nl` | de het een en van is dat op te voor met zijn niet aan er ook als bij door naar wordt deze maar om uit |
| `de` | der die das und ist nicht mit den von zu ein eine auf fur dem des sich auch als wird bei oder sind dass werden |
| `fr` | le la les des et est un une du dans que pour qui pas sur au par avec ce sont ne plus cette ou aux |
| `es` | el la los las de que en un una es por con para del se no como mas su al lo son pero este |
| `it` | il la di che un una per in con non del della le sono si da come piu anche dei nel alla gli |
| `pt` | os as de que em um uma para com nao do da por se dos das mais como ao sao na |
| `ro` | si in de la cu este un care pe din sau pentru nu se mai sunt ca prin al ale aceasta fie intre |
| `pl` | nie na sie do to ze jest jak ale po co tak za od dla przez sa lub oraz byc moze |

`decideLanguage`, in this order:

1. `requested` is not `"auto"` → `{ language: requested, source: "user" }`.
2. `guess.kind === "clear"` → `{ language: guess.top, source: "material" }`.
3. `guess.kind === "mixed"` → `{ ask: [guess.top, guess.second, locale] }` without duplicates.
4. Otherwise → `{ language: locale if it is in SUPPORTED_LANGUAGES, else "en", source: "portal" }`.
