## Things most likely to go wrong (review these at the end)

1. **A wrong or guessed owner link** (`/manage/<token>`) must give a 404 and must not reveal whether a
   course exists. The token is never logged and never stored in clear text outside the job state.
2. **The admin page without a session** must show only the login form; every admin server action must
   check the session itself (a page-level check does not protect an action).
3. **An edit that makes a course invalid** (last lecture removed, lecture left with no content) must be
   refused with a clear message and must leave the stored course unchanged.
4. **Old data**: a job created before this iteration (it may have `bundleReady`, or step `publish` /
   `publish-wait`) and a course whose `meta.json` has only `jobId` and `publishedAt` must keep working.
5. **Missing translation**: a key that exists in English but not in Romanian must fail a test, not
   show a raw key to the user.
6. **Settings take effect immediately**: pausing generation or disabling an invite code in `/admin`
   must apply to the next request, without a redeploy.
7. **The animated background must not weaken the CSP** and must not move for users who ask for
   reduced motion.

### Task A1: Publish inside the `finish` step

Today a job goes `finish → publish → publish-wait → done` through a `Publisher` interface that was
designed for GitHub. There is only one publisher left, so fold it into `finish`.

**Files:** modify `lib/jobs/state.ts`, `lib/jobs/steps.ts`, `lib/jobs/runtime.ts`,
`lib/sites/store.ts`, `lib/api/handlers.ts`, `tests/jobs.test.ts`, `tests/sites.test.ts`,
`tests/routes.test.ts`; create `lib/sites/publish.ts`; delete `lib/publish/` (both files).

**Interfaces to produce (exact names):**

```ts
// lib/jobs/state.ts
export type Step = "plan" | "review" | `lecture:${number}` | "finish" | "done";
export interface JobState {
  id: string; step: Step;
  status: "idle" | "working" | "awaiting-review" | "done" | "failed";
  lecturesTotal: number; lecturesDone: number; attempts: number;
  error?: string;        // an error CODE from Task B1, never a sentence
  siteUrl?: string;      // "/courses/<key>/"
  manageUrl?: string;    // "/manage/<token>", set when the job is done
  codeId?: string;       // which invite code created the job (Task C2); never sent to the browser
  usage: { inputTokens: number; outputTokens: number; calls: number };
  createdAt: string; updatedAt: string;
}

// lib/sites/store.ts
export interface SiteMeta {
  formatVersion: 1;
  jobId: string; publishedAt: string; updatedAt: string;
  title: string; lectures: number;
  usage: { inputTokens: number; outputTokens: number; calls: number };
  ownerHash: string;     // sha256 hex of the owner token
}
export const OWNER_TOKEN: RegExp;                       // /^[A-Za-z0-9_-]{32}$/
export function newOwnerToken(): string;                // randomBytes(24).toString("base64url")
export function ownerHash(token: string): string;       // sha256 hex
export async function writeSite(store: Store, key: string, site: SiteData, meta: SiteMeta): Promise<void>;
// also writes `owners/<ownerHash>.json` = {"key": "<key>"}
export async function readMeta(store: Store, key: string): Promise<SiteMeta | null>;
// tolerant: a meta file with only jobId and publishedAt is completed with defaults
// (formatVersion 1, updatedAt = publishedAt, title "", lectures 0, usage zeros, ownerHash "")
export async function findCourseByOwnerToken(store: Store, token: string): Promise<string | null>;
// null unless OWNER_TOKEN matches, the owners/ file exists, AND that course's meta.ownerHash equals the hash
export async function deleteSite(store: Store, key: string): Promise<boolean>;
// now also deletes `owners/<meta.ownerHash>.json` when ownerHash is not empty
export async function listCourses(store: Store): Promise<{ key: string; meta: SiteMeta }[]>;
// from store.list("courses/"), newest publishedAt first, at most 200

// lib/sites/publish.ts
export function siteFromFiles(key: string, files: Record<string, string>): SiteData;
// the parsing that lib/publish/portal.ts does today (isBundlePath check, courseSchema, lectureFileSchema, buildSiteData)
export async function publishCourse(store: Store, input: {
  key: string; files: Record<string, string>; jobId: string;
  usage: JobState["usage"]; now: Date;
}): Promise<{ siteUrl: string; manageUrl: string }>;
```

**Behaviour:**

- `nextStep`: `finish → done`. Remove its `publishConfigured` parameter.
- `runStep` for `finish`: validate as today, then `publishCourse(...)` with
  `key = courseKeyFor(plan.course.id, state.id)`, delete `materials.json`, return the state with
  `step: "done"`, `status: "done"`, `siteUrl`, `manageUrl`. Do **not** write `bundle.json` any more.
- `AdvanceDeps` loses `publish`. `runtimeDeps` no longer builds a publisher.
- Old jobs (Review item 4): at the start of `advance`, a state whose step is `"publish"` or
  `"publish-wait"` is treated as step `"finish"` with `attempts: 0`.
- `publicJob` (in `lib/api/handlers.ts`) returns `manageUrl` only when `status === "done"`, and never
  `usage` or `codeId`.
- The usage stored in `meta.json` is the job's usage **including** the finish step.

**Tests (write first; memory store, canned model):**

- A full job ends `done` with `siteUrl` matching `/courses/<key>/` and `manageUrl` matching

- `readMeta` on a file `{"jobId":"x","publishedAt":"2026-11-11T10:00:00Z"}` returns the defaults above.

| Code | HTTP | When |
| --- | --- | --- |
| `generation-off` | 503 | generation disabled, paused, or the model is not configured |
| `too-large` | 413 | body over 4 MB |
| `bad-request` | 400 | not JSON, wrong shape, unknown language/level, invalid options |

routing" (read it in `node_modules/next-intl/` or its README link).

**Files:** create `i18n/config.ts`, `i18n/request.ts`, `messages/en.json`, `messages/ro.json`,
`app/actions/locale.ts`, `components/LanguageSwitch.tsx`, `tests/messages.test.ts`; modify
`next.config.ts` (wrap the existing config with `createNextIntlPlugin("./i18n/request.ts")`; keep
`headers()` and `skipTrailingSlashRedirect`), `app/layout.tsx`.

```ts
// i18n/config.ts
export const LOCALES = ["en", "ro"] as const;
export type Locale = (typeof LOCALES)[number];
export const DEFAULT_LOCALE: Locale = "en";
export const LOCALE_COOKIE = "locale";

// cookie if it is a known locale; else the first known locale in Accept-Language; else "en"
```

- `i18n/request.ts`: `getRequestConfig` that calls `pickLocale` with the cookie and the

- `app/layout.tsx`: `<html lang={locale}>` and `NextIntlClientProvider`. Keep the existing metadata but
  take `title` and `description` from the messages.
- `app/actions/locale.ts`: server action `setLocale(locale: string)`: ignore unknown values; set the
  cookie for one year, `path: "/"`, `sameSite: "lax"`.
- `components/LanguageSwitch.tsx` (client): two buttons "EN" / "RO" with `aria-pressed`; calls

**Message files.** Nested JSON, one namespace per page: `common`, `landing`, `create`, `job`,

**Romanian rules** (the text must read as written by a native speaker, not word for word):

- Use the informal singular ("tu"): "Adaugă fișierele", not "Adăugați".
- Use correct diacritics: ă, â, î, ș, ț (comma below, not cedilla).
- Glossary — always use these: course site → "site de studiu"; lecture → "lecție"; outline →
  "cuprins"; quiz → "test"; interactive widget → "exercițiu interactiv"; access code → "cod de acces";

- Keep the brand "playground." untranslated.

"ţ" (cedilla forms). `pickLocale`: cookie wins; `ro-RO,ro;q=0.9,en;q=0.8` → `ro`; `de-DE` → `en`;

### Task D1: Patch logic (pure, no UI)

**Files:** create `lib/sites/edit.ts`, `tests/site-edit.test.ts`.

```ts
// lib/sites/edit.ts
export interface CoursePatch {
  title?: string;                                   // 1..120 characters after trim
  description?: string;                             // 0..400
  accent?: string;                                  // #rrggbb
  lectures?: { slug: string; title?: string; remove?: boolean }[];
  blocks?: { slug: string; sectionId: string; index: number; remove?: boolean; md?: string }[];   // at most 200
}
export const coursePatchSchema: z.ZodType<CoursePatch>;       // strict objects
export type PatchError = "unknown-lecture" | "unknown-block" | "not-editable" | "last-lecture" | "empty-lecture" | "invalid";
export function applyCoursePatch(site: SiteData, patch: CoursePatch): { ok: true; site: SiteData } | { ok: false; code: PatchError };
export function blockSummary(block: Block): { kind: string; text: string; editable: boolean };
// text: the first 140 characters a person would recognise the block by (md, title, prompt, caption, first item…);
// editable: true only for kinds "prose" and "info"
```

Rules for `applyCoursePatch` (never mutate the input; work on a deep copy):

1. `title` sets `course.title`; when `course.shortTitle` was equal to the old title, set it too.
   `description` sets `course.description`. `accent` sets `course.theme.accent` (create `theme` when
   missing; keep `corners`).
2. `lectures[].title` sets `meta.title` of that lecture. An unknown `slug` → `unknown-lecture`.
3. `blocks[]` address a block by lecture `slug`, section `id` and the block's **original** index in
   that section. Unknown → `unknown-block`. `md` is allowed only when the block's kind is `prose` or
   `info` (it replaces the block's `md` field; at most 6,000 characters) → otherwise `not-editable`.
   Apply all `md` changes first, then removals from the highest index to the lowest.
4. A section with no blocks left is removed. A lecture with no sections left → `empty-lecture`.
5. Lectures with `remove: true` are dropped. No lecture left → `last-lecture`. Renumber
   `meta.number` 1, 2, 3 … in the remaining order.
6. Rebuild `site.index` from the lectures with `toIndexEntry` (`@core/assemble`).
7. The result must pass `siteDataSchema` → otherwise `invalid`.

Tests: one test per rule and per error code; the input object is unchanged after a call
(`structuredClone` before, deep equal after); an empty patch returns a site deep-equal to the input;
removing a `custom` block works (this is how a creator removes a model-written exercise they do not
want); `md` on a `table` block gives `not-editable`.
